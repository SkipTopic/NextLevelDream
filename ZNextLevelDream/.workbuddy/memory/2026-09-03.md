### Bug 修复（用户反馈：写日记后再读，位置不是记入的位置）

- **根因**：`GameState.save_diary()` 写盘时使用的是 `current_scene_path` / `player_position` 两个变量，但这两个变量只在 `_ready()` 里被 `record_position()` 写一次。HUD 的 Y 键 / 写日记按钮路径从未刷新，所以存下的是"进入该场景时的落点"。
- **修复**：在 `GameState.save_diary()` 内部强制调用新增的 `capture_player_position()`（深度优先找 `Player` 节点、抓实时 `global_position` 与当前场景路径）。所有路径（Y 键、HUD 按钮、书桌）共享同一个写入函数。
- **回归测试**：保留 `tools/test_diary_save.gd`，临时挂为 Autoload 跑，验证 5 个场景的存档 → 读档 → 落点零误差（深林因随机树宽容到 40px）。最新一次结果 5/5 PASS。
- **体验改进**：HUD 写日记反馈从"✓ 这一刻被写进了日记"改为"✓ 记下 主通道 (1600, 380)"，用户能直接看到写入了哪个世界 + 哪个坐标。
- **顺手补的体验缺口**：Nexus 主通道原本只有 4 扇门（红/绿/蓝/黄）和 Q 醒来两条路，缺少回梦境卧室的回程传送门。在 Nexus (1440, 1080) 加了一个紫色 portal → DreamBedroom (1230, 420)，从入口一进门正下方就能看到。

## 关键设计决定

1. 玩家用 CharacterBody2D + motion_mode=Floating（无重力），速度 320 px/s。
2. 交互用"朝向探针"——玩家前方 96px 的 Area2D CircleShape2D r=76。
3. SpriteFrames 在 `_ready()` 用 AtlasTexture 程序化拼出，美术替换只换 sprite sheet。
4. 场景切换统一走 `SceneFader.change_scene(path, fade_out, fade_in, landing)`。
5. 存档走 JSON + 版本号；存档写盘前一定先抓实时坐标。
6. 主通道里每个梦境世界对应一个 `Interactable` 门 + 一个回程 portal，世界自身的底部 portal 直接回主通道。
